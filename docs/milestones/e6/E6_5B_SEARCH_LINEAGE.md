## Durable search lineage

After exact fold/plan binding but before first replay, the grid executor commits a SearchReservation into the existing SQLite hash-chained command journal. It pins the manifest digest, research plan digest, full arm count and the stability policy (before any evidence for this plan). One immutable reservation per plan, exact retry idempotent; a changed policy or manifest is rejected. Legacy histories remain replayable; evidence already present without a reservation is not retroactively declared unseen. Reserve against all previously registered development windows in the same DB: exact data-tape digest or same stable instrument with overlapping validation interval. A later registration cannot reuse a reserved validation interval as a new validation window. Existing holdout reservations still apply. Prior train data may not become a fresh search validation window. Prior validation may be used as subsequent training, but not represented as a fresh search validation. This is conservative (even registered but unexecuted windows can prevent reservation).

Every returned full search matrix, including FAILED arms, is recorded as canonical sorted outcome rows, referencing the existing exact report SHA for successful arms. No raw tape, exception text, or fake zero PnL. Conflicting/missing/duplicate keys or unknown report hashes fail closed. Success after failure appends a new outcome snapshot; identical latest snapshots are idempotent. Locking validation in a reserved search requires the latest full matrix to have all arms recorded and candidate to pass both ordinary candidate gates and the frozen stability policy. No automatic selection is performed by search itself. If execution crashes before returning the matrix, the reservation and any already recorded evidence survive, but the interrupted attempt has no full outcome snapshot. This is not a physical retry counter; same-plan retries and separate databases remain possible. External prices, code, aliases and raw data use are not controlled. This is local collision/lineage protection, not authenticated proof of an unseen dataset or durable externally anchored tamper-proof log. Legacy non-search plans retain prior behavior.

## Descriptive robustness

For each validation window compare candidate normalized net return against the better of the matching cash and entered-hold baselines, using the worse excess of base and stress cost conditions. Require paired complete evidence; no hold entry means missing evidence. Group windows by overlapping UTC calendar days across instruments (transitive overlap); no correlated same-day instruments counted as separate chronological blocks. Average their worse-cost excess per block, then weight each block equally in descriptive summary. Report matched/planned window counts, block scores, positive block fraction, worst block excess and worst leave-one-block-out mean (remove best block). Missing block suppresses complete-block statistics; low sample support, provisional inputs, failed latest relevant arm or missing baseline produce INCONCLUSIVE. Ordinary evidence rejection or violation of concentration gates produces UNSTABLE; STABLE is a research diagnostic only. The ordinary risk and fill gates still apply. No inference that blocks are independent, no confidence interval or significance p-value, and no formal multiple-testing correction.

Default preregistered hypothesis: at least 3 time blocks, strictly positive excess in at least 67% of blocks, worst block excess >= -1 percentage point, and worst leave-one-block-out mean >= 0. These values are implementation defaults chosen for conservative demonstration, not calibrated investment criteria; a two-fold experiment necessarily lacks default support. Once reserved, parameters cannot be changed for that plan.
