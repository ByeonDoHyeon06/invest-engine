## Scope

A fixed-rule validation orchestrator, not yet supervised learning or optimized parameter selection. Supply frozen ORB parameter candidates, cash/entered-hold comparators, one explicit strict E5 minute tape/calendar per registered fold/instrument, two matched cost configs, a common risk/allocation target and code/source identifiers. Every window has 20 warmup sessions, within the declared fold historical bounds. The strategy gets only its own E5 tape. Warmup observations may be from the causal pre-evaluation embargo; no supervised labels are fitted and no training cutoff is represented as model fitting. Fixed rule identities use development-start cutoff. The initial ResearchPlan train window is not a fitted data artifact and is not used by this runner.

Prepare validation by recomputing the walk-forward plan from timing metadata, verifying all folds and instruments present exactly once, checking strict E5 minute validation and requiring every scored event ID and observation time match the eligible validation timing sample. If a validation label has been purged, this strict runner rejects the entire instrument/fold instead of quietly scoring removed observations. Fold end bounds are UTC elapsed durations; strict market windows may be contained within these spans but every eligible scored sample must match exactly. No final holdout input.

Each scenario uses same settlement/instrument/risk/target settings with base/stress fees, penetration buffer, participation and adverse exit; stress costs must be monotonic by configured fee/tax/spread/impact and participation. The structural policy comparison does not certify exchange or retail charges. Candidates are session-flat protected ORB using existing E5 logic; BuyHold retry is first-entry-only with no fabricated entry; cash benchmark never trades. All fresh E5 engine and strategy instances, equal independent starting cash per arm, currency-specific reports; no capital compounding across folds. Expose E5's existing config digest formula as a pre-execution method without changing existing hash values. Pin every initial config, scenario, fold metadata, raw event hash and policy in the window's context before the caller registers its ResearchPlan in the SQLite journal. Exact matrix/candidate/baseline/holdout metadata is checked again before running. Report bridge reconciles the event tape, report, timing, fees and metrics; stores canonical report hash and provisional evidence. Partial runtime errors return explicit FAILED arm status and are not replaced with zero returns. Successful runs remain in the journal, retries deterministically re-execute and idempotently reconcile before lock. Failure summary itself is returned, not yet persisted; no automatic lock or holdout execution. All imported evidence flags remain unverified. A profitable backtest cannot automatically pass.
