## API

- PipelineSpec: immutable plan ID, explicit registration timestamp, WalkForwardSpec, bounded SearchGrid, economic/stability policies, label horizon, one declared initial training and reserved final metadata window per instrument, optional regime/exposure diagnostic config. Stable universe/currency/partition bounds required. Initial training descriptors are claims, not fitted model/data artifacts; final windows are claimed hashes/ranges, not tapes.
- prepare_pipeline(spec, timing, cases, scenario): compile timestamp-only walk-forward, require eligible complete strict E5 case matrix, generate fixed candidates and baselines, pin data and scenario config and search identities; construct canonical ResearchPlan and reservation with deterministic digest. No market replay during preparation. Caller supplies development timing and event data only; no holdout prices, labels or execution input.
- run_development(journal, prepared, timing, cases, scenario): recompute and compare the full prepared value before registering; require exact durable plan and reservation before first replay; run complete matched strategy/control base/stress arms; preserve report evidence, failed-outcome matrices and descriptive stability; generate the review. No implicit lock or tuning. Exact retry is idempotently reconciled. Registration and reservation are distinct local transactions; a crash between them may leave a registered, not-yet-reserved plan with zero replayed arms.
- review_pipeline(journal, prepared): rebuild development-only review, verify journal plan/reservation identities, expose planned/recorded/latest failed/incomplete/unverified arms, canonical outcome history hash, latest outcomes, candidate economic/stability assessments, phase, blockers and locked identity. No market tape needed if the caller retains the prepared plan. Export canonical JSON bytes and digest; detailed regime reports remain caller-owned.
- close_validation(journal, prepared): explicit irreversible close of complete validation matrix; incomplete/failed latest matrix cannot close. The registry alone chooses any eligible candidate; provisional or unsuccessful candidates are not selected. This workflow does not execute/finalize the separate holdout. Repeated close returns current review. No method provides production approval.

Phase contract: RETRY_REQUIRED, NO_ELIGIBLE_CANDIDATE, READY_FOR_EXPLICIT_VALIDATION_LOCK, VALIDATION_CLOSED_NO_CANDIDATE, CANDIDATE_LOCKED_OFFLINE. A complete provisional matrix is not a pass. Successful E5 imports remain unverified on data provenance, execution and cost attestations. All phases return production_authorized=false. Closing a provisional run reserves it permanently in the local journal; no future evidence replacement is offered. Do not close on behalf of an operator who wants to retain it for research inspection.

## Scope/limitations

This is offline deterministic fixed-rule search, not self-learning, autonomous capital management, financial strategy recommendation, promotion or selected-candidate holdout executor. No evidence authenticity or source acquisition is introduced by this orchestration. The local journal controls declared windows/tape hashes/arm IDs only, not actual unseen data, external file access, separate database copies, or privileged tampering. The caller retains the PreparedPipeline and detailed output artifacts; recovery of summary uses that prepared value and existing SQLite history, not a self-contained full manifest serializer. The registered-at timestamp and initial/final dataset metadata are caller assertions. E5 data acceptance, PIT/corporate actions and dated fee verification, trusted independent report attestations, untouched final tests and actual robustness across independent historical data remain required. No real performance claim; no route to broker or trading authorization.
